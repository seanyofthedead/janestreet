## Project Overview

Autonomous multi-strategy trading agent for Alpaca **paper trading only**. Combines OCaml/Melange type-safe trading core with TypeScript services and a Next.js dashboard. Equities only, no live trading.

## Architecture

**Monorepo with npm workspaces** (`engine`, `dashboard`, `watchdog`, `backtest`).

- **`trading-core/`** — OCaml source (requires OCaml 5.4+, Melange 6.0+, Dune 3.20). Built in WSL2, compiled to JS via Melange. Contains risk management, signals, position sizing, portfolio math. Design principle: make illegal states unrepresentable.
- **`trading-core-js/`** — Generated JS output from Melange build. Do not edit directly; regenerated by `npm run build:ocaml`.
- **`engine/`** — TypeScript trading engine (entry: `src/main.ts`). Orchestrates strategies (mean reversion, momentum, market making), connects to Alpaca API/WebSocket, manages state in DynamoDB. Uses pino logging, zod validation.
- **`watchdog/`** — TypeScript risk monitor with kill switch and health checking. Independent process that can halt trading.
- **`dashboard/`** — Next.js 15 + React 19 + Tailwind CSS 4 real-time monitoring UI. TanStack Query for data fetching, Recharts + lightweight-charts for visualization. Route handlers in `app/api/`.
- **`backtest/`** — Backtesting runner (entry: `src/runner.ts`).
- **`scripts/`** — Setup and build scripts (DynamoDB table creation, OCaml build, startup).

**Data flow:** OCaml core (compiled to JS) → Engine imports via `@trading-core/*` path alias → Engine executes trades via Alpaca API → Watchdog monitors independently → Dashboard reads from Engine/Watchdog APIs.

## Build & Run Commands

```bash
# Install dependencies
npm install

# Build OCaml core (runs in WSL2, copies JS output to trading-core-js/)
npm run build:ocaml

# Start everything (DynamoDB Local + PM2 services)
bash scripts/start-all.sh

# Individual services
npm run dev:engine      # tsx watch engine/src/main.ts
npm run dev:dashboard   # next dev
npm run dev:watchdog    # tsx watch watchdog/src/main.ts

# PM2 management
npx pm2 logs [engine|watchdog|dashboard]
npx pm2 stop all
npx pm2 restart all

# Tests (per workspace)
npm test --workspace=engine
npm test --workspace=watchdog
npm test --workspace=backtest

# Single test file
npx vitest run path/to/test.ts --workspace=engine

# Build TypeScript
npm run build --workspace=engine
npm run build --workspace=dashboard

# Docker Compose (all services + DynamoDB)
docker compose up -d
```

## OCaml Development (WSL2)

OCaml toolchain lives in WSL2 Ubuntu 22.04 at `~/janestreet`. opam binary at `~/bin`.

```bash
# In WSL2:
eval $(opam env)
cd ~/janestreet
dune build @melange        # Build Melange JS output
dune build                 # Build native
dune runtest               # Run OCaml tests
```

## Environment

Copy `.env.example` to `.env`. Requires Alpaca paper trading API keys. DynamoDB Local runs via Docker on port 8000. Services: engine :3001, watchdog :3002, dashboard :3000.

## Key Conventions

- TypeScript workspaces use ES modules (`"type": "module"`) with `tsconfig.base.json` shared config
- OCaml modules use variant types and pattern matching for domain modeling (account phases, order types, risk states)
- The `@trading-core/*` path alias maps to `trading-core-js/trading-core/lib/*`
- Integration tests live in `test/integration/`
- Vitest is the test runner for all TypeScript workspaces
